# E-learning Mobile Platform

## Contexto

La plataforma de e-learning buscaba ofrecer una experiencia de aprendizaje desde dispositivos móviles. El proyecto formó parte de mi trabajo en DaCodes, donde participé desde una perspectiva de UX y Product Design, con énfasis en entender las necesidades de los usuarios antes de definir la experiencia del producto.

El reto no era únicamente diseñar una aplicación móvil. Era entender cómo las personas interactúan con una plataforma de aprendizaje, qué necesitan para avanzar dentro de ella y qué partes de la experiencia podían convertirse en fricción.

Mi participación se enfocó en la investigación y en transformar los hallazgos en decisiones de producto y diseño.

# MLSToolbox — Code Assessment

## Contexto

Durante mi estancia en Barcelona trabajé en **MLEvol**, un proyecto de investigación enfocado en la evolución continua y eficiente de sistemas de Machine Learning.

Dentro de este proyecto trabajé con **MLSToolbox**, una herramienta low-code que permite diseñar visualmente pipelines de Machine Learning y generar código Python.

Mi trabajo se concentró en **CodeAssessment**, un módulo que analiza código Python utilizado en pipelines de Machine Learning.

Mi contribución consistió en añadir capacidades de análisis al sistema existente, utilizando análisis estructural del código para producir métricas que ayudaran a evaluar diferentes características de los pipelines.

El proyecto combinó software engineering, análisis estático de código y una capa de visualización para convertir información técnica en información utilizable dentro de una herramienta web.

**Mi rol:** Software Engineer / Research  
**Proyecto:** MLEvol / MLSToolbox  
**Organización:** GESSI — UPC Barcelona  
**Tipo:** Contract  
**Año:** 2025  
**Timeline:** Septiembre–diciembre 2025  
**Equipo:** [PENDIENTE: integrantes y roles exactos]

---

## Problema

Los pipelines de Machine Learning pueden crecer rápidamente en complejidad. Evaluar su estructura y calidad requiere analizar características que no siempre son evidentes al revisar el código manualmente.

CodeAssessment ya proporcionaba una base para analizar pipelines Python, pero existía una oportunidad para ampliar las capacidades del sistema y convertir más características estructurales del código en métricas que pudieran ser interpretadas desde la herramienta.

Mi trabajo no consistió en crear CodeAssessment desde cero. Añadí una nueva capacidad de análisis al sistema existente.

El reto era determinar:

- qué características del código debían analizarse;
- cómo extraerlas de manera consistente;
- cómo representar los resultados;
- y cómo integrarlos dentro del flujo existente de CodeAssessment.

**[PENDIENTE: ¿Cuál era exactamente la pregunta de investigación o producto que el equipo quería responder con las nuevas métricas?]**

## Proceso

El trabajo comenzó entendiendo la arquitectura existente de CodeAssessment y la forma en que la herramienta procesaba los pipelines Python.

### Análisis del código

Para extraer información estructural del código utilicé análisis del **Abstract Syntax Tree (AST)**, permitiendo inspeccionar la estructura del programa más allá de simplemente ejecutar el pipeline.

El análisis se complementó con herramientas como **Radon** y **Pylint** para obtener información relacionada con características de complejidad y calidad del código.

Entre las métricas consideradas en el proyecto se encontraban:

- FCPP
- SCPP
- CCPP
- LCCML
- LPCML
- PDSC
- IFC-M
- IFC-P
- PFP
- PMCR
- FPC
